# פתרון בעיות

זהו תחילה את החיבור הכושל: שגיאת תצורה מקומית, חיבור לקוח MCP לשרת או בקשה יוצאת ל-Google. תקנו את השכבה הרלוונטית והריצו שוב את הפעולה שנכשלה.

## התחלה ללא רשת {#start-offline}

```sh
mcp-gmap-rs --version
mcp-gmap-rs tools
mcp-gmap-rs doctor
```

`doctor` מדפיס JSON גם כשהבדיקות נכשלות. בדקו קוד יציאה ואת `checks[].status`: הערכים `pass`, `fail` או `not_tested`. בדיקות לא מקוונות אינן מוכיחות IAM, הפעלת API, חיוב, אמון/תוקף תעודה או גישת ADC. `/health` מוכיח רק חיות תהליך.

אם קובץ dotenv מקומי לא תקין חוסם גילוי, `--no-env-file tools` מדלג עליו. הדבר עשוי לשנות את קבוצת הכלים שנבחרה, ולכן אין לראות בכך אימות לתצורת הקובץ המיועד.

## פירוש כשלים נפוצים {#interpret-common-failures}

| תסמין | הבדיקה הבאה |
| --- | --- |
| `GOOGLE_MAPS_API_KEY is required` | נבחר מצב מפתח API או שהפעולה מגיעה לנקודת קצה התומכת רק במפתח. |
| `GOOGLE_CLOUD_QUOTA_PROJECT is required` | הגדירו מזהה או מספר פרויקט צרכן ל-OAuth. |
| Google 403 / API לא פעיל | הפעילו את ה-API המדויק בפרויקט הצרכן של פרטי הגישה; בדקו חיוב והגבלות מפתח. |
| `serviceusage.services.use` נדחה | העניקו לחשבון השירות `roles/serviceusage.serviceUsageConsumer` בפרויקט המכסה; אפשרו הפצת IAM ונסו שוב. |
| דחיית IP של מפתח API | התירו את כתובת היציאה הציבורית של השרת או האשכול, ולא את ה-IP הפרטי של ה-Pod. |
| MCP HTTP 401 | שלחו את אסימון bearer של השרת; אסימון גישה של Google מאמת חיבור אחר. |
| Host/Origin נדחו | התאימו בדיוק ל-Host ולמקור הדפדפן המוגדרים, כולל פורטים. |
| HTTP 429 מ-MCP | המגביל של התהליך מוצה; כבדו `Retry-After` ובדקו מקביליות לקוחות. |
| פסק זמן OAuth | בדקו קישוריות לאסימון, STS, IAM או מטא-נתונים, שעון מערכת ופסק זמן לבקשה. |
| חיבור TLS נכשל | בדקו שרשרת תעודות, שם מארח, אמון ותעודת mTLS אופציונלית בנפרד מהרשאת HTTP. |
| יציאה 0 אך נתונים חסרים | בדקו שגיאות לפריט במטריצה ובכלים משולבים, ולא רק קוד יציאה של התהליך. |

## אימות מכוון של גישה חיה {#verify-live-access-deliberately}

בדיקות חיות מבצעות קריאות העשויות להיות כרוכות בתשלום. צמצמו אותן לממשקים הנדרשים:

```sh
mcp-gmap-rs --enabled-tools maps_weather doctor --live
```

בדיקה מוצלחת אינה מבטיחה כל אזור או פעולה. אחרי שינוי ב-Google Cloud, הריצו שוב את אותה קריאה כושלת במקום להסיק הצלחה מהגדרות המסוף. ראו [אימות זהות](./authentication) ל-IAM ולמקורות פרטי גישה, [תצורה](./configuration) לקדימויות ו[תפעול ייצור](./production) לתקציבים, מועדים ומדדים. אין להדפיס JSON של פרטי גישה או לצרף את כל הסביבה לדיווח תקלה.
